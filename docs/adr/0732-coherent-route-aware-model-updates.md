# 0732: Coherent model updates with available frontiers

- **Status**: Accepted
- **Date**: 2026-11-17

## Context

A globally stronger model can suppress useful rungs in workspaces whose providers cannot serve it.
Coding observations from unidentified evaluation cohorts can also produce misleading comparisons.
Model registration alone leaves ladders and automatic defaults behind the new catalogue.

## Decision

Require `update-lucidos-models` for additions across chat, Claude Code and Codex.
Ship registration, routing, pricing, reasoning, menus, coherent estimates, ladder review and default review together.

Generate every pair's dominating identities offline, including dominators outside the global frontier.
The Lucidos Agent default frontier keeps available pairs without an available dominator and retains its available current default.
Availability uses the router's selected route, supported efforts and existing account capability authorities.
Unknown listings preserve configured eligibility; explicit provider pins and known refusals retain their meaning.
Catalogue support and saved owner lists remain separate from automatic availability filtering.

Use one documented, comparable cohort for active coding observations and calibration.
Keep exact model, effort, harness and evaluation evidence privately, alongside archived historical inputs.
Missing measurements remain explicit estimates through the documented fallback; never copy observations between efforts.
Publish only estimate bands, flags and pair identities.

Review defaults using capability and cost, including cache and long-context rates.
Prefer current supported generations when justified, without silently upgrading to substantially costlier successors.
Preserve stored model/effort preferences and recorded thread selections.

## Rationale

Offline dominance metadata preserves exact comparisons without shipping raw benchmark figures or reconstructing scores from coarse bands.
Runtime availability prevents unconfigured or excluded models from removing usable defaults across provider populations.
A comparable benchmark cohort makes measured and estimated coverage auditable.
A mandatory shared workflow prevents model menus, estimates and defaults from drifting independently.

GPT-6.2 Sol shares GPT-6.1 Sol's standard input, output and cache rates, justifying its OpenAI-family and Codex default upgrade.
GPT-6.2 Astra costs four times Sol on those rates, so it remains a premium option.
Historical background evaluation rosters remain attached to the models they measured.

## Consequences

The policy covers packaged and source workspaces on macOS and Linux across single-provider and mixed-provider configurations.
Execution still requires a configured provider or a coding-agent CLI accepting the model.
Provider changes can alter automatic Lucidos Agent rungs without rewriting saved preferences or hiding catalogue entries.
Coding cohort refreshes can deliberately change existing coding estimates; unrelated calibration stays pinned unless separately reviewed.
Generated subset parity, route integration, default preservation and import rejection tests protect these contracts.

## Alternatives considered

- **Filter the global frontier after generation.** Unavailable winners already removed useful candidates, so this cannot recover the correct subset frontier.
- **Store only global frontier dominators.** A removed dominator can itself dominate another available pair; arbitrary subsets need all identities.
- **Recompute scores from bands.** Rounding loses comparisons, and publishing raw figures crosses the benchmark privacy boundary.
- **Probe paid model calls for eligibility.** Existing routing and capability authorities suffice without another cache or paid request.
- **Mix historical coding observations without cohort proof.** Unknown evaluation compatibility cannot support a comparable calibration.
- **Upgrade defaults by release recency.** A new generation can materially increase cost; default changes need a recorded price and capability rationale.
