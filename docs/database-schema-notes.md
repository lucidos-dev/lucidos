# Database schema notes

`crates/lucidos-engine/migrations/` is the schema authority. Each migration names its columns, constraints and indexes. This page holds what the SQL does not say: who writes a table, which invariant a constraint protects, and what reads it. [`.claude/rules/db.md`](../.claude/rules/db.md) holds the conventions that apply to every table. [`docs/system-events.md`](system-events.md) holds the matching event notes.

## Tables

### Events and changes

- **`events`.** `trigger_chain_depth` and `emitting_trigger_id` record what the live broadcast carried to the trigger matcher. A scheduler lag replay then dispatches a row as the live frame did (ADR 0137 amendment). `NULL` reads as depth 0 and no emitting trigger. Within one thread, commit order equals `sequence` order (ADR 0360). Every append with a `thread_id` takes the thread append lock right after its in-flight append lock.
  - Across threads there is no such guarantee. Only a per-thread reader may treat `sequence > mark` as gap-free, and a global reader takes its mark from `committed_event_horizon` (ADR 0364).
- **`changes`.** `status` is `pending`, `set_aside`, `applied`, `discarded`, `reverted` or `withdrawn` (ADR 0400). `idx_changes_unique_open_branch` allows one `pending` or `set_aside` row per `branch_name`. A `withdrawn` row holds no slot. `incomplete` marks only the archive net's set-aside rows.
  - `summary` is NULL until `ChangeSummarized` lands for the current `description`. `repo_root` can hold a workspace root for an app coding-agent thread, so Apply routes by `thread_summaries.coding_agent_kind`, never by its shape.
- **`hardened_branches`.** The harden marker. `tier` is `fast` or `full`. Only `git_ops/harden_marker.rs` writes it. A fast marker counts only for an integrated sub-thread. Every other reader asks for a full one.
- **`planned_branches`.** The plan marker store, keyed by canonical (symlink-resolved) `repo_root` and `branch_name` (ADR 0154). `state` is `proposed` (a plan file exists but no human approved it, so it does not satisfy the gate), `planned`, `acknowledged_simple` or `bounded_security_fix`. Only `proposed` and an absent row block. A CHECK pairs `files` with the state: non-empty for `bounded_security_fix`, NULL for every other state, so no write path records a bound nothing enforces.
- **Plan marker lifecycle.** `lucidos planned mark --plan` records `proposed`. `lucidos planned approve` flips it to `planned` with a targeted UPDATE that keeps `plan_path`. `mark --simple` records `acknowledged_simple`. `mark --security-fix` records `bounded_security_fix` with no approval step.
- **Plan marker readers.** The `cc-plan-gate` PreToolUse hook reads it through `GET /api/v1/internal/planned-state`. The Apply floor (`change_ops/apply.rs`) reads it for Lucidos-source threads only. For a `bounded_security_fix` row the floor refuses a branch whose landing (committed diff plus uncommitted worktree files) leaves `files`.
  - The check runs at both apply entry points. It runs again in `completion.rs` for a conflict-resolution merge. It never runs at the tier fast paths, because an `Err` there reads as "main diverged, escalate". Helpers live in `git_ops/plan_marker.rs`.

### Thread projections

- **`thread_summaries`.** A projection the EventBus maintains. `last_user_action` bumps only on user-initiated events, and `last_agent_action` only on agent or trigger events. `last_activity` stays the maximum of both. `get_saved_threads` orders by `last_user_action DESC`, so background agent churn never reshuffles the Saved section.
  - `last_agent_action` drives the thread-row tooltip's "Agent" line. Facets, the family-extension cap and the `list_thread_summaries` surface keep `ORDER BY last_activity`.
- **The Archive pile orders and paginates by `created_at DESC`.** That covers `get_older_threads` (cursor filter and ORDER BY), the `/threads/older` cursor, the frontend `byCreated` sort (`sortDrawerSections`) and the global `ROW_NUMBER` window in `get_recent_threads`. The window partitions by `archive_state = 'archived'` across all sources, never per source: a union of per-source `created_at` prefixes cannot page gap-free through one cursor.
- **The outer `WHERE` of `get_recent_threads` is only `archive_state = 'inbox'` or the contiguous archived window.** An archived `failed` or `waiting_for_user_answer` thread reaches the drawer through `created_at` pagination at its true date. An archived `proposed` state is impossible: a pending in-workspace change has no Archive action (`is_blocking`), and external-repo archiving applies the change before `ThreadArchived`. The inner candidate filter keeps `coding_agent_change_state = 'proposed'`, so an inbox row with no response still surfaces.
- **`archive_state` defaults to `'inbox'`**, so fresh rows are never silently archived.
- **`blocking_descendant_count` and `attention_descendant_count`.** Both are roll-ups that `propagate_blocking_change` (`event_bus_projection.rs`) maintains in lockstep. The first counts transitive descendants that prevent this thread's archive (`is_blocking` in `thread_lifecycle.rs`). The second drops the `Running` case, so `is_blocking = is_attention_needing OR status == Running`. `available_thread_actions` reads the first, and `display_section` reads the second to bubble the ancestor chain to Review.
- **`coding_agent_kind`** is `lucidos`, `app` or `external`, with `coding_agent_folder` the canonical folder the spawn targets. It is not backfilled. The engine writes a non-NULL `cc_repo_id` for Lucidos-source threads too, so `cc_repo_id IS NOT NULL` cannot mean external. NULL reads as `lucidos` through `CodingAgentKind::parse`. `apply_change` dispatches on it through `load_apply_kind_context`.
- **`coding_agent`** is `claude-code` or `codex`. The `SessionStarted` arm writes the newest session's backend, keeping the old one when the event names none. Only a *successor session* may start on another backend (ADR 0560). NULL reads as Claude Code through `CodingAgent::parse`. Backend resolution (`run_direct_agent`), `validate_thread_continuity` (a mismatched follow-up returns 409) and `thread_coding_agent` read it.
- **`coding_agents`** (`TEXT[]`, empty when none) lists every backend a session started on, first use first, each once. The `SessionStarted` arm appends the event's backend when absent, and `ContinuationStarted` leaves it alone. The drawer draws one mark per entry.
- **`coding_agent_change_state`** is `none`, `unproposed` or `proposed` (ADR 0400). Detail sits in `coding_agent_unproposed_reason` and `coding_agent_requires_restart`, and `CHECK` constraints enforce both couplings. `sync_thread_proposal` owns `proposed`, `branch_work_sql` moves between `none` and `unproposed`, `ProposalWithheld` writes the reason, and a turn start or a set-aside `ChangeProposed` clears it. Every Archive and Delete gate reads `proposed`. Read the three columns back through `CodingAgentChangeState::from_columns`. The same `CodingAgentIdled` arm moves `none` and `unproposed` from `payload.has_changes`.
- **Compose-draft columns.** `compose_text`, `compose_images`, `compose_mode` and `compose_selection` are written directly by `PUT /threads/:id/compose`, which makes the row the authoritative draft store. The compose UPDATE uses `COALESCE($n, col)` on them, so a text-only keystroke preserves the rest. A NULL `compose_selection` means no per-draft picks.
- **`compose_epoch` is the write fence for that PUT.** It counts submissions, not writes. The PUT takes the client's last-heard value and adds `AND compose_epoch = $n`. A write composed before a submission is then refused with 412 and the current compose report.
  - An absent value skips the precondition for cached clients. `consume_compose_slot` moves it once per accepted submission (ADR 0450). No projection arm moves it for a composer submission, and `ThreadDiscarded` deliberately does not.
- **The compose revision is `summary_version`.** Every compose writer returns a compose report (`ComposeReport`, `core/store/threads/compose.rs`) read in the same statement as the compose fields. The client orders reports by `summary_version` alone (ADR 0437).
- **`compose_updated_at`** dates the last applied compose PUT, the only writer of non-empty draft text. A submission that clears the draft leaves it alone. NULL means the draft predates the column. `GET /api/v1/threads/drafts` reads it as `last_edited`. "Holds a draft" has one definition, `HAS_DRAFT_SQL` and `has_draft` in `core/store/threads/drafts.rs`.
- **`summary_version`** is the schema's one trigger-owned column (ADR 0329). It rises by one on every change to the row and never otherwise. An insert starts it at 0 and a write to it is overridden. Never set or bump it by hand. The client orders every summary by it. A second trigger only forces `read_requested` FALSE.
- **`parent_thread_id`** is also the `parent` filter on `/threads/list` and `/threads/count`, direct children only. It is written at spawn and changed once at most: `ChildThreadDetached` on the former parent sets it to NULL and rebases `depth` over the subtree (ADR 0278). The spawn event keeps the old parent, so read parent-ness from this column, never from `MessageReceived`.
- **`parent_callback_pending`** is the child-side fan-in marker (ADR 0011). TRUE means the parent callback for this child's current run is not delivered yet. The spawn upsert and the revive helper write TRUE, only for a row with a parent. The `ChildThreadCompleted` arm clears it in-tx.
  - It collapses a coding-agent child's terminal storm into one completion card, so every read is `is_coding_agent`-gated. A user Stop (ADR 0252) leaves it TRUE on purpose, because the card is still owed. So does a turn that ends holding a live event wait (ADR 0254). A move to top level clears it with the edge.
- **`is_stopped_child`** is TRUE while a user Stop has ended a child's turn and nothing has settled it (ADR 0252). The `ResponseCanceled { user_stop }` arm sets it, only on a row with a parent and a pending marker. `mark_parent_callback_pending` and the settling `ChildThreadCompleted` arm clear it. It feeds `is_attention_needing` and never `is_blocking`.
- **`parent_wake_requested`** is a child's wake decision for its current turn. `ParentWakeRequested` sets TRUE, `ParentWakeNotRequested` sets FALSE, and `mark_parent_callback_pending` resets it to NULL on every start event. `settle_parent_callback` spends it. Only FALSE on a clean finish files the report. A child with a `wake_mode` ignores its FALSE.
- **`wake_mode`** is `no-wake`, `wake` or `wake-when-all-done`, declared by the spawn (ADR 0451). The spawning `MessageReceived` writes it in the INSERT that writes `parent_thread_id`, and nothing changes it after. NULL means undeclared.
- **`apply_in_flight`** is TRUE from `ApplyNowStarted` to `ApplyNowEnded` (ADR 0437). Clients read "applying" from it and nothing else. `end_interrupted_applies` clears a flag a stop left set at startup.
- **`enabled_mcp_servers`** is the thread's set of server ids (ADR 0430). `ThreadMcpServerEnabled` and `ThreadMcpServerDisabled` change it, and `McpServerStopped` and `McpServerRemoved` remove the id from every row. A turn reads it to build its MCP slice, and dispatch refuses a tool of a server the thread did not enable.
- **`read_requested`** is TRUE while the agent's request to read its latest reply goes unseen (ADR 0409). `ThreadReadRequested` sets it. `ThreadReplySeen`, a human message and `ThreadArchived` clear it. `ThreadReadNotRequested` never touches it.
  - It is FALSE while a change already lists the thread, whether proposed (Review) or unproposed for `hardening_missing` (Blocked). The SQL function `change_replaces_read_request` defines those states, and the trigger `thread_summaries_read_request_yields` applies it for every writer (ADR 0421). It makes a trigger run attended in `is_unattended`. It feeds neither `is_attention_needing` nor `is_blocking`.
- **`live_event_waits` and `live_event_wait_count`** are the event waits the thread itself holds. The list is JSONB entries `{wait_id, on, reason, expires_at}` copied from `EventWaitStarted`. One statement per projection arm writes both (`event_wait_sql` in `event_bus_projection_thread.rs`), and the count derives from `jsonb_array_length`, never an increment, so the pair cannot disagree. `EventWaitStarted` filters by `wait_id` then appends, so a replay converges. A resolution naming an unknown `wait_id` moves neither column.
- **Neither wait column is a roll-up**, so there is no ancestor walk. The count has two readers: `resolveVisualStatus`, and `available_thread_actions`, which withholds Apply and Discard while it is non-zero (ADR 0106). `is_blocking`, `is_attention_needing` and `display_section` read neither, so a subscribed thread stays archivable (ADR 0049). Relaxing `is_blocking` is unsafe: it stops an ancestor cascade-archiving the thread, and that cascade emits `ChangeApplied` per pending change. The client cannot derive them, since its own fold covers only loaded events.
- **`waiting_children_count`** counts direct children that are not in flight and hold a live event wait (ADR 0254). It stays disjoint from `active_children_count`, and the frontend adds them. It is never incremented: `reconcile_parent_waiting_children_count` recounts from ground truth, and `rebuild_children_counts` repairs both counts on boot and after a delete.
- **`successor_thread_id` and `successor_of`** are the two links of a legacy successor thread, both projected from the old thread's `SuccessorThreadSpawned`. A *successor session* sets neither (ADR 0560). The projection writes `successor_thread_id` only while it is NULL and fails the emit otherwise, so a racing second handoff leaves no trace. A row whose `successor_of` equals its `parent_thread_id` is a retired build chain's builder (ADR 0503), whose planner stayed open. A handed-off row's `parent_callback_pending` stays FALSE.
- **`coding_agent_integrated`** marks an integrated sub-thread (ADR 0465). The child's first `MessageReceived` writes it from the `integrated` flag on its queued `AgentChat` request, and `SessionStarted.integrated` writes it too. It is monotone, so nothing clears it.
- **`keep_alive_turn`** is TRUE while a cache keep-alive turn runs. `EventBus::mark_keep_alive_turn` sets it. The turn's idle, a question or permission card, and boot clear it. While it is set, the projection skips that turn's output events, so the thread keeps its status, section and counts.
- **`cache_keep_alive_status`** is JSONB, NULL when nothing is warm. Only `CacheKeepAliveStatusChanged` writes it, and only the keep-alive tick emits that, on a change. The tick also clears the status of every thread that left candidacy.
- **`cache_keep_alive_off_at`** is when the user last turned the keep-alive off for this thread, the `created` of its latest `CacheKeepAliveTurnedOff`. `CacheKeepAliveTurnedOn` clears it. The switch holds only while it is later than the thread's last real request, so a stale value is harmless (ADR 0554).
- **`is_home`** marks the home thread (ADR 0362). `HomeThreadCreated` writes it. A partial unique index allows one per workspace, and two CHECKs keep the row unarchived and parentless.
- **A voice call writes more columns than the row suggests** (ADR 0167). `VoiceSessionStarted` bumps `last_activity` and `last_user_action` only. Each spoken row then bumps the same pair, with `SpokenReplyGenerated` taking `last_agent_action` instead. Both set `has_response`, and `SpokenMessageReceived` fills `first_message` under COALESCE.
  - Those two make a call the agent never worked on reachable. They also promote `state` from `composing` to `active`, clear the compose fields and bump `compose_epoch`. The session start does not, so a call nobody spoke on stays a discardable draft. `status` is never touched, since the agent's turn owns it (ADR 0149).

### Queues, batches and standing applies

- **`thread_queue`.** Holds background entries only, `queued` or `admitted`. `request` is the full re-executable `ThreadQueueRequest`. Rows exist while an entry is live, and `events` keeps the audit trail. Boot rebuilds the manager's memory (`recover_persisted_entries`) with one rule for all four kinds (ADR 0133).
  - An admitted row whose thread exists hands off to thread-level recovery. One that bound no thread re-queues. Duplicate cron rows for one trigger collapse to one, keeping the oldest, so a restart storm cannot re-stack a cron backlog.
- **Cron holds at most one entry per trigger.** A cron fire carries no distinct payload, so `submit` coalesces a redundant fire. `max_queued_per_trigger` and `overflow` apply only to event triggers.
- **User-initiated work is not a row** (ADR 0008). `acquire_user_slot` tracks it in memory, because a dead response is gone on restart and never re-fires. The panel API merges it in as `kind: "user-chat"`.
- **`apply_all_batches`.** The durable membership mirror of the in-memory registry (`engine::apply_all_batches::ApplyAllRegistry`). It stores membership only. Per-member resolution comes from `changes.status`. `start_apply_all_batch` inserts the row, and `persist_batch_removed` deletes it wherever the registry drops the batch.
  - `recover_apply_all_batches` runs at boot after agent recovery. A `pending` member queues again unless a session owns it, and a fully resolved batch emits the missing `ApplyAllBatchCompleted` so the toast clears (ADR 0314).
- **`standing_applies`.** One arm per thread (ADR 0168 clause 5), so re-arming replaces. `change_id` binds the arm to exactly that change, which keeps it off a second change the thread proposes later. NULL means a sweep armed a still-working thread, so it takes whatever that thread proposes. `batch_id` names the Apply All sweep, so `POST /api/v1/changes/apply-all/cancel` drops everything it armed.
  - `insert_arm` and `take_arm` are module-private to `engine::standing_apply`. Rows exist while an arm is live. `recover_standing_applies` re-takes every verdict at boot, so a thread that settled while the engine was down gets its apply.
- **`thread_input_chains`.** Admission bookkeeping (ADR 0449). Admission (`engine::chat::input_order`) writes it under the thread append lock. An input is admitted past `last_seq`, or as a repeat of the tail, else refused with 409 `overtaken`. No foreign key exists, since a thread's first input is admitted before its first event creates the `thread_summaries` row. Rows are deleted with their thread.

### Notifications, devices and preferences

- **`notifications`.** A projection of `NotificationCreated`. `tap` is a JSONB union, `{"kind":"modal"}` (the default, and the only kind for info-only notifications) or `{"kind":"navigate","to":{...}}`, which delegates to the `navigate_ui` router. A CHECK enforces the two kinds. The `none` kind is retired: every notification is openable.
  - Historical events keep `none` forever, because events are immutable, so the custom `Tap` deserializer (`scheduler/notifications.rs`) coerces it to `Modal` on replay. `event_id` names the event inside `thread_id` that raised it, and the in-app matrix uses it for the "user looking at source event" auto-read check. It differs from `tap.to.event_id`, which is the scroll-and-pulse target.
- **`devices` and `push_subscriptions`.** `devices.last_seen_at` is stamped on every page load (`DeviceStore::register`) and when the device hides Lucidos (`DeviceStore::mark_seen`). Neither stamp announces. "Seen" in the agent's Known devices list is the newer of it and `device_presence.visible_at`.
- **`device_presence`.** A transient projection with no `events` rows. `DevicePresenceStore::candidates` returns devices that pinged visible in the last 2 minutes (`PRESENCE_STALE_AFTER`). It is the secondary input to the PresenceCheck gate. `send_push_to_all_with_app` runs the protocol when `max(engine.sse_connections.count(), candidates.len()) > 0` (`expected_pong_count` in `scheduler/push.rs`) and skips it only when both are zero. The live SSE count is primary, because it does not go stale when iOS suspends the heartbeat.
- **`preferences`.** Key-value store with optional `device_id` scoping. It holds no secret.
- **`environment_variables`.** User-managed non-secret variables, `name` matching `^[A-Z_][A-Z0-9_]*$` and not engine-reserved, `value` plaintext on purpose. `EnvironmentVariableStore` (`core/environment_variables.rs`) does CRUD and `env_pairs()`, which filters reserved names. They inject fresh per spawn through `build_script_env_vars` and `apply_lucidos_env`, before engine-owned variables, so the engine always wins. `apply_to_process_env` also applies them to the engine's own env at startup, and a change there lands on the next restart.

### Secrets and credentials

- **Secret columns.** Every column in `SECRET_COLUMNS` (`core/secret_store/`) holds only sealed secrets (`lsec1:...`), and a `<table>_<column>_sealed` CHECK refuses anything else (ADR 0509). A new secret column joins `SECRET_COLUMNS` with its CHECK in the same change, and a guard test fails otherwise. The agent role gets column `SELECT` on the other columns of these tables and no writes. `MOVED_SECRET_COLUMNS` keeps a column the boot check still reads until its drop.
- **A migration cannot edit a secret's contents in SQL**, because it sees only ciphertext. That change runs in Rust after the key loads. `secret_store::one_home` is the example. At boot it files each old `email_accounts.password` as an `email_password` credential and drops the column. It also moves each `mcp_servers.env` value of a row whose `env_credentials` is NULL into a `secret` credential named `mcp-<server id>-<VAR>`.
- **`vapid_keys`.** The Web Push keypair, one row. `private_key_pem` is a sealed secret. `scheduler/push.rs` writes it.
- **`backup_recipient`.** One row. `recipient` is an age public key, NULL before the switch, and seals every new archive. `pending_recipient` is a minted pair's public half, which seals nothing until the user pastes its backup key back. No column ever holds a backup key. Only `core/backup/recipient.rs` writes it, and it is read-only to the agent role, so an agent cannot redirect backups to its own key.
- **`credentials`.** `auth_type` is the discriminator, and `service_name` carries no namespace prefix. Two constraints replace the single name key: `UNIQUE (service_name, auth_type)`, and a partial `UNIQUE (service_name) WHERE auth_type <> 'oauth_client'`. The asymmetry is load-bearing. Names stay globally unique for every type injected as `CRED_<NAME>` or resolved by bare name, and only `oauth_client` may shadow one.
  - `CredentialStore::get` adds `AND auth_type <> 'oauth_client'`, which keeps the bare-name readers correct (provider keys in `llm/provider_build.rs`, the `apis.json` resolvers in `api/proxy.rs`). Typed reads use `get_oauth_client`, `get_email_password` and `get_typed`. `upsert_row` picks its `ON CONFLICT` target by type.
- **Credential HTTP verbs on an existing row take `id`.** That covers `PUT` and `DELETE /api/v1/credentials` and `GET /api/v1/credential-value`, since a name identifies at most a pair and the edit form can change `auth_type`. `POST` stays name-keyed because it is an upsert.
- **`base_urls` is the credential scope** (ADR 0161): every base URL the credential may be presented to. `credential_scope_covers` passes when any member covers the outbound URL, with no wildcard and no suffix rule. `scope_members` is the store's floor, with no blank member storable. On the update verb, absent `base_urls` keeps the stored set and an explicit `[]` clears it. `PUT /api/v1/credential-base-urls?id=<uuid>` replaces the set and nothing else. A singular `base_url` on a body is permanent back-compat.
- **`scope_declared`** records that someone decided the scope, an empty set included. Every write path sets it. `CredentialStore::infer_undeclared_scopes` (ADR 0144 decision 4) fills an empty scope from `apis.json` only on an undeclared row, then declares every row. So the inference runs once and never refills a scope a user emptied.
- **`env_var_name`** is an optional alias. `named_credential_env_vars` also injects the secret under that name (ADR 0516), in addition to `CRED_<NAME>`. It applies to single-value types only, and `password` keeps its `_USERNAME` and `_PASSWORD` split. `environment_variables::validate_name` validates it at the API boundary.
- **An `oauth_client` row is never injected as `CRED_*`.** Its `auth_value` is a plaintext JSON blob only the OAuth flow reads, and it is the per-credential source of truth for the flow's endpoints. `authorize_params` absent means `access_type=offline&prompt=consent`.
- **A secret field may hold a secret reference** (`op://vault/item/[section/]field`) inside the sealed `auth_value`. It resolves only when used, through `Credential::secret` (`core::secret_reference`), and the resolved value is never written back.
- **An `onepassword_service_account` row** is not `AuthType::is_injectable`. `get` and `find_by_url` exclude it, no `CRED_*` names it, reveal refuses it, and only `CredentialStore::onepassword_service_account` reads it.
- **`oauth_accounts` and `email_accounts`.** `email_accounts` holds no password. IMAP and SMTP read the account's `email_password` credential, so deleting it ends mail access. The table is read-only to the agent role, since a writable host would send the password elsewhere at the next login. `oauth_accounts.scopes` is what the provider granted.
  - `desired_scopes` is what the account was asked for, and it accumulates monotonically (`granted ∪ previous_desired ∪ requested`). *Reconnect* re-requests `desired_scopes`, so a provider-narrowed account can recover. NULL means never recorded, and a legacy account is never narrowed.
- **`claude_gateway_accounts`.** At most one row, keyed by `singleton BOOLEAN PRIMARY KEY CHECK (singleton)`. It stays apart from `oauth_accounts` on purpose, because every reader of that table hands a token on. A gateway token must reach only the gateway, and only when `issuer` equals the configured origin. Only `ClaudeGatewayAccountStore` (`llm/claude_gateway/account.rs`) writes it. `sign_in` and `sign_out` announce.
  - `forget_rejected` deletes the row only while it still holds the rejected token. The silent `update_tokens` matches on `issuer` and the refresh token it spent, so a refresh racing a sign-out cannot overwrite the row. Both tokens are sealed, so those checks lock the row and compare in Rust.
- **Managed settings columns.** `managed_settings`, its etag and fetch time, and `managed_telemetry_since` hold the gateway policy. A new sign-in resets all four. `store_managed_settings` writes only while `issuer` and `created_at` still name the sign-in it fetched for, and announces a changed document as `ClaudeGatewayManagedSettingsChanged`.
- **`claude_gateway_telemetry_cursor`.** One row. `sent_through` is the last `events.sequence` the exporter (`llm/claude_gateway/telemetry/exporter.rs`) sent or skipped. It moves only after a `2xx`, or past captures it skips (no sign-in, telemetry off, or made before `managed_telemetry_since`). The first run seeds it at the committed event horizon, so history is never sent.
  - `opted_out` is set by an engine whose environment opts out. The next pass without the opt-out skips to the horizon and clears it in one `UPDATE`. Only the exporter reads it.

### Registries and configuration

- **`mcp_servers`.** `env_credentials` maps an env variable to a credential name, a pointer and never a value. `launch_env` resolves each name at start. NULL marks a row whose sealed `env` values boot has not moved yet. The cached tool manifest (`tools`, `tools_observed_at`) comes from `McpServerStore::set_tools`, called after `McpClient::connect` succeeds, so a failed start leaves the previous manifest intact.
  - It is the table's one silent writer, a registered `ExemptWriter`. NULL `tools_observed_at` means never observed, and `GET /api/v1/mcp/servers` reports `tools_source: "never-observed"` for it.
- **`disabled_tools` holds wire names** (`mcp__<server>__<tool>`), the spelling the permission allowlist and dispatch key on. `get_tool_definitions` filters them out of every request, and `call_tool` refuses one at dispatch. Dispatch is the enforcing half, since an in-flight call or a resumed turn carrying old definitions would otherwise still run. `set_tool_disabled` switches one tool per call under a row lock.
- **`models`.** Plain config, authoritative like `mcp_servers` and `credentials`. `id` is the model's identity and default wire id. `routes` is an ordered JSONB list of `{provider, id?, context_window?}` (ADR 0247). The `model_routes_valid` IMMUTABLE function backs a CHECK that refuses an empty list, a malformed element and a provider named twice.
  - `context_window` NULL means the id-shape guess reads this route's id. `preferred_provider` is the per-model memory of the last provider picked.
- **Route resolution** (`llm::model_registry::resolve_route`) takes the preferred route when its provider is configured, else the first configured route. An explicit choice is honoured or refused, never substituted. A first-party Claude id is byte-identical on Vertex and Anthropic, so neither route spells one. OpenRouter needs it.
- **Context windows err low on purpose.** Under-declaring only trims early, and over-declaring makes the provider reject the request. Most bare `claude-*` routes stay NULL, because 1M mode is gated on Lucidos's own `[1m]` suffix, which adds the 1M-context beta in `build_claude_request`. A family whose default window is 1M declares 1000000. `declared_window` drops a non-positive stored value.
- **More `models` columns.** `vision` says whether the model reads images, and image description calls only a flagged model (ADR 0379). `default_effort` is the tier the model runs at when nothing stored names one, and NULL sends no effort (ADR 0390). `every_builtin_declares_whether_it_reads_images` and `every_builtin_declares_its_default_effort` force a later seed to decide. `successor` names the model a retired model moved to, written only by the `retire_model(old, successor, accepted_efforts)` SQL function, read-only to the API (ADR 0418). `source` is `builtin` (never deleted) or `user`.
- **The `ModelRegistry` is in memory** (`HashMap<String, ModelRouting>`), reloaded on `Model*` events. It drives the picker, `RoutingProvider` route selection and the context trim budget. The Claude Code `/model` picker is separate: Claude Code's discovered model list (ADR 0325), with `runtime/cc_menu_options.json` as the fallback.
- **`chat_ladder_upgrade_models`.** Models a workspace had `enabled` when the ladder migration ran, snapshotted only on a database that already had events. At the next boot `runtime::chat_ladder::upgrade_from_enabled` writes them into the `intelligence_ladder_chat` override unless one is set, then empties the table so the upgrade runs once.
- **`repositories`.** `id` is deterministic: `RepositoryStore::register`, the single write path, sets `uuidv5(REPO_ID_NAMESPACE, root_commit_sha)`, falling back to the path when the repo has no commits. Re-registering, moving or renaming the same history yields the same id, so `thread_summaries.cc_repo_id` bindings never orphan. The upsert keys on `id` and collapses stale rows. No FK references `id`: `repo_names.id` and `cc_repo_id` share the id space by convention (`docs/glossary.md` § "deterministic repo id").
- **`repo_names`.** Keeps the name of every repo ever added, so a removed repo still resolves a name. `RepositoryAdded` upserts it, and `RepositoryRemoved` deliberately does not touch it. `RepositoryStore::register` (`core/repositories.rs`) is the only reachable way to write a `repositories` row, so no mutation path skips the projection. It emits only when a user-visible field moved, so the boot re-registration of the Lucidos source repo adds no row per restart.
  - A marker-guarded startup backfill, `backfill_repo_names_from_changes`, recovers names for repos that predate the event from `changes.repo_root`, with `ON CONFLICT DO NOTHING`. `repo_name_expr` reads `COALESCE(repositories, repo_names)`.
- **`app_kinds`.** Keeps the kind (`app` or `widget`) of every removed app folder (ADR 0404). The thread filter then still lists a removed widget as a widget. EventBus upserts it from `AppDeleted` when `kind` is set. `get_filter_facets` reads it. There is no backfill.
- **`summary_tree_nodes` and `summary_tree_scopes`** (ADR 0362). A derived index rebuildable from events, so nothing announces a write (`Silent` in `announced_surfaces.rs`). `scope` is `workspace` or a thread uuid as text. `span` is a power of 2 with `start % span = 0`, both CHECKed.
  - Only `engine/summary_tree/store.rs` writes them. `POST /api/v1/threads/delete` purges the family's trees in its one transaction through `store::delete_family`, including every workspace merge ending past the first deleted leaf. `reflected_through` is the newest event sequence a scope reflects, so a restart re-queues only scopes with newer events. `backfilled_at` is the per-workspace ready flag, CHECKed to the `workspace` row.
- **Partial indexes on `events`.** `idx_events_summary_tree_workspace_leaves` serves the eight workspace leaf event types, spelled as literals in the query so the planner can use it. `idx_events_summary_compaction_captures` serves the backfill estimate over compactor `ContextCaptured` rows.

### Webhooks

- **`webhooks`** (ADR 0097). `event_type` is the pinned domain event every delivery emits. Neither secret-bearing column holds a secret: `token_hash` digests a token shown once, and `hmac.credential` names a `credentials` row, the only home for a signing secret. The CHECK `webhooks_needs_a_verifier` refuses a row with neither, so a public endpoint with nothing to verify is not storable. Only `WebhookStore` (`core/webhooks.rs`) writes it, and it emits from inside its write paths.
- **`webhook_deliveries`.** A nonce ledger, not a delivery log (ADR 0122, ADR 0444): no payload, no list surface, and its only reader is the next delivery. The row commits in the domain event's own transaction. The bus calls `DeliveryLedger::record` after it opens the transaction and before it inserts the event. No row back means a resend, so the transaction rolls back and the first event id answers.
  - A dropped handler or a restart rolls back, so no row exists without its event. `delivery_key` is always a SHA-256 digest of `header:<value>` or `body:<body>`, so a caller's header is never stored raw. Only `DeliveryLedger` writes it (`Silent`). `prune_webhook_deliveries` sweeps daily at 03:10 UTC to `MAX_WINDOW_SECS` (7 days). The same constant caps a configurable window, so the sweep never drops a row still deciding a duplicate.
- **Delivery outcome stamps** (`last_accepted_at`, `last_refused_at`, `last_refusal_reason`; ADR 0143). "Arrived and was refused" and "never arrived" share one symptom, no events, so a rotated secret otherwise looks like a dead ingress. `WebhookStore::{record_accepted,record_refused}` write them from `api::webhooks::deliver` once the verdict is settled. A failed UPDATE is logged and dropped, because a verified, emitted delivery must not fail on a bookkeeping write. They are observations, so nothing is emitted and `updated_at` stays put.
- **`last_refusal_reason` reaches the owner and never the sender**, because an endpoint that says why it refused helps whoever is guessing. The ingress probe's own unsigned POST stamps nothing: it carries a token that cycle minted, and `deliver` skips the stamp on a match. Otherwise a healthy workspace would report a refusal every 15 minutes.
- **The refusal run** (`refusal_run_count`, `refusal_run_since`, `refusal_run_cause`, `refusal_run_reasons`; ADR 0235) records what the hook has turned away since it last accepted anything. The stamps hold only the last refusal, so a diagnostic probe overwrote the field an investigator came to read. `refusal_run_reasons` is keyed by `DeliveryRefusal::key()`, a closed set, so nothing a sender controls reaches it. `record_refused` takes the enum and writes all four columns in one statement.
- **A run is homogeneous in its cause.** A refusal of the other cause restarts the run. Otherwise a hook switched off after an hour of signature failures would read as having discarded all of them unread. The start is kept while the cause holds, so the run can age past the declaring window. `record_accepted` clears the run whole and is the only writer that does. Both writers are `ExemptWriter`s, and the verdict announces instead, as `WebhookDeliveries{Refused,Recovered}`.
- **Every age is measured in SQL, never against the engine's clock** (ADR 0053). `WEBHOOK_COLUMNS` carries two computed columns, so `core::webhook_refusal::judge`, which is pure, takes no clock. A host ahead of a drifting database would otherwise read every run as negative seconds old and judge `Clear` for good. For a hook that is on, the clock reads the refusals' own span, `run_secs - quiet_secs` (ADR 0365). `GET /api/v1/webhooks` returns a nullable `refusal_run` object.

## Querying events

The timestamp column is `created`, not `created_at`. `aggregate_id` is `text`, so cast when joining: `aggregate_id = c.thread_id::text`. The `thread_id` column is legacy, so prefer `aggregate_id`. `payload` is `jsonb`.
