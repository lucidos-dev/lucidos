# Lucidos Environment Variables

Full reference. The `DATABASE_URL` password-in-argv rule also lives in the root
`CLAUDE.md` (it is a safety rule, so it must be resident even when this skill
is not loaded) — the two must stay in sync.

- `LUCIDOS_WORKSPACE` — workspace dir (default `./workspace`)
- `DATABASE_URL` — Postgres connection string for the engine. **Never hardcode the URL or password into a `psql`/Python invocation** — the engine sets `PGUSER`/`PGPASSWORD`/`PGHOST`/`PGPORT`/`PGDATABASE` in every spawned subprocess (CC sessions, bash + python tools, scheduled scripts), so just run `psql -c '…'` bare. Putting the URL in argv leaks the password into the persisted `Bash` tool-call payload that the steps UI renders.
- `LUCIDOS_MODEL` — LLM model (default `claude-opus-5@default`). `[1m]` = 1M context. `gpt-*` = OpenAI.
- `VERTEX_PROJECT_ID` / `VERTEX_REGION` — GCP (default region `europe-west1`). The project also resolves WITHOUT this env var, so a packaged build works from a user's existing `gcloud auth application-default login`: the engine reads the ADC file (`$GOOGLE_APPLICATION_CREDENTIALS` → `$CLOUDSDK_CONFIG`/`~/.config/gcloud/application_default_credentials.json`) and refreshes the access token itself — no `gcloud` binary — and resolves the project from the ADC `quota_project_id` or the gcloud config `[core] project` (resolution order: env → ADC/config files → `gcloud config` subprocess). Only the `authorized_user` ADC type is read in-engine; other types fall back to the `gcloud` subprocess (dev only). See `crates/lucidos-engine/src/llm/vertex/adc.rs`.
- `OPENAI_API_KEY` — for `gpt-*` models (fallback for the `openai` provider when no `openai` credential is set). Below this the engine has a further, lowest-precedence fallback: it auto-detects a key from the Codex CLI's auth file (`${CODEX_HOME:-~/.codex}/auth.json`, `apikey` login only — a `chatgpt`/OAuth login is ignored), the parallel of Vertex reading the gcloud ADC file. Full resolution order: stored `openai` credential → `OPENAI_API_KEY` → Codex-detected key. The detected key is read fresh at provider-build time and never persisted. See `crates/lucidos-engine/src/llm/openai/codex_detect.rs`.
- `LUCIDOS_OPENROUTER_API_KEY` — fallback for the `openrouter` provider (e.g. GLM 5.2 `z-ai/glm-5.2`) when no `openrouter` credential is set
- `LUCIDOS_LOCAL_BASE_URL` / `LUCIDOS_LOCAL_API_KEY` — base URL + optional key for the `local` OpenAI-compatible provider (Ollama / LM Studio / vLLM / llama.cpp). Base URL defaults to Ollama `http://localhost:11434/v1`; also settable via the `local_base_url` preference (Settings → Providers). The local provider is built only when a base URL or key is configured.
- `LUCIDOS_EMBEDDING_MODEL` — embedding model (`bge-small-en-v1.5` or `multilingual-e5-small`, default `multilingual-e5-small`)
- `LUCIDOS_EXTRACTION_MODEL` — default model the memory extractor falls back to when no per-call override is passed and the `model_memory` preference is also empty (default `gemini-3-flash-preview`)
- `LUCIDOS_CODEX_PROTOCOL` — which protocol drives Codex sessions: `app-server` (default — persistent JSON-RPC child; permission cards, streaming, graceful interrupt) or `exec` (per-turn `codex exec` escape hatch, sandbox-only guard). See ADR 0005.
- **Network bind** (security: defaults to loopback-only everywhere; a malformed value fails safe to loopback, never to all). Resolution precedence, highest first: `LUCIDOS_BIND_LOOPBACK` (engine only, the behind-gateway floor; a fronted packaged engine never faces the network) → `LUCIDOS_BIND_ADDR` / `LUCIDOS_GATEWAY_BIND_ADDR` (a literal IP, e.g. a Tailscale `100.x` address) → `LUCIDOS_BIND_ALL` / `LUCIDOS_GATEWAY_BIND_ALL` (`1` = all interfaces, `[::]` dual-stack) → the machine-global `~/.lucidos/network.toml` → loopback. The engine + gateway resolvers live in `crates/lucidos-{engine,gateway}/src/net_config.rs` (duplicated per ADR 0014 §1). `~/.lucidos/network.toml` (`[gateway] bind = "loopback" | "all" | "<IP>"`, `[engine] inherit = true|false`) is the durable, UI-editable config both binaries read at boot: the gateway binds `[gateway].bind`; an engine binds the gateway's bind when `inherit` (default) or its own per-workspace `network_bind` preference when not. Env vars override the file so launch scripts / e2e are unaffected. **A specific `<IP>` bind ALSO binds `127.0.0.1` (loopback retention, `net_config::bind_socket_addrs`).** A single specific-IP socket excludes loopback, but every co-located caller reaches these processes over loopback: the gateway proxies + health-probes its engines at `127.0.0.1:<port>`, the dev scripts POST the gateway control API over `localhost`, and the engine's Apply-restart callback hits `127.0.0.1:<gateway_port>`. So binding ONLY the tailnet IP wedged the gateway↔engine hop ("Opening your workspace" forever); binding the IP **and** loopback fixes it without widening external exposure (loopback is host-only; `loopback`/`all` already cover it, so only the specific-IP case adds a socket). Edited from the picker (machine-global, `/~/api/v1/control/network-config`) and per-workspace Settings → Access → Network access (`/api/v1/network-config`). A change takes effect only after a gateway/engine **restart** (a live socket cannot be re-bound). If an engine can never be reached past a budget (`BOOT_ESCAPE_BUDGET`, gateway `server.rs`) the boot splash escapes to a manual "Back to workspaces" link rather than refreshing forever.
- `LUCIDOS_TAILSCALE_BIN` (absolute path to the Tailscale CLI) overrides the built-in candidate probe in `lucidos_tailscale::resolve_tailscale_binary` (one copy, shared by the engine, the gateway and the desktop app). Unset (the norm) probes `/usr/local/bin/tailscale`, `/opt/homebrew/bin/tailscale`, `/usr/bin/tailscale`, then falls back to bare `tailscale` on `PATH`. The macOS `Tailscale.app` GUI executable is deliberately excluded: it is not a CLI, headless it exits **0** while printing `Tailscale.CLIError error 3`, and since the probe stops at the first EXISTING candidate it would shadow the working CLI on every Mac that has the app. Absolute-path probing exists because the **packaged app has no `PATH` at all** (Finder/launchd), so a bare-name spawn silently failed there. **Scope: actions only.** Since 2026-08-02 the Network access "Detected Tailscale" hint and the Mobile Access tailnet state are read from the machine's interface list with no CLI, so this variable affects only **Settings → Access**'s Sign in and Expose buttons (`tailscale up` / `tailscale serve`). Neither detection nor this override can change what a process binds to.
