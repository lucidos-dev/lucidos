# Database Schema Reference

Lucidos uses **event sourcing** — the `events` table is the central source of truth. Thread metadata cached in `thread_summaries` (projection maintained by EventBus).

## Key tables

| Table | Purpose |
|---|---|
| `events` | Event store. Columns: `id` (uuid), `event_type` (text), `payload` (jsonb), `created` (timestamptz), `thread_id` (uuid), `sequence` (bigserial), `aggregate` (text), `aggregate_id` (text). |
| `changes` | CC proposed changes. Columns: `id`, `request_id`, `branch_name`, `repo_root`, `description`, `file_count`, `files` (text[]), `requires_restart`, `status` (`pending`/`applied`/`discarded`), `created_at`, `resolved_at`, `thread_id`. `repo_root` legitimately holds a workspace root path (not just a registered repo root) for *app coding-agent thread* changes — apply routes by `thread_summaries.coding_agent_kind`, not by `repo_root` shape. |
| `thread_summaries` | Projection — cached thread metadata (title, source, last_activity, message_count, is_saved, has_response). Maintained by EventBus. `archive_state` column defaults to `'inbox'` (since `20260518132821_blocking_count_running_overrides_archived.sql`) — fresh rows are not silently archived. Also carries `blocking_descendant_count` (INT, default 0) — rolled-up count of transitive descendants currently in a state that prevents this thread's archive (Running, WaitingForUserAnswer, or has_pending_changes on a non-external-repo CodingAgent thread — see `is_blocking` in `thread_lifecycle.rs`; Running / WaitingForUserAnswer block regardless of `archive_state`). Consumed by `available_thread_actions(..., descendants_block_archive: bool)` via `count > 0`; maintained by `propagate_blocking_change` in `event_bus_projection.rs`. AND `attention_descendant_count` (INT, default 0, added by `20260522091904_add_attention_descendant_count.sql`) — strict subset of `blocking_descendant_count` that DROPS the `Running` case. Counts transitive descendants in WaitingForUserAnswer OR with pending changes (CC && !external_repo) — the user-attention subset, per `is_attention_needing` in `thread_lifecycle.rs`. Consumed by `display_section(..., has_attention_descendants: bool)` via `count > 0` to bubble the ancestor chain to REVIEW. Relationship: `is_blocking = is_attention_needing OR status == Running`. Maintained by the same `propagate_blocking_change` walk in lockstep with `blocking_descendant_count`. ALSO carries `coding_agent_kind` (TEXT, nullable, added by `20260527131839_add_coding_agent_kind_and_folder_to_thread_summaries.sql`) — `'lucidos' \| 'app' \| 'external'` — and `coding_agent_folder` (TEXT, nullable) — the canonical folder the spawn targets (`<ws>/data/apps/<id>/` for App, repo root otherwise). **Not backfilled** — the engine writes a non-NULL `cc_repo_id` for both Lucidos-source and external threads (Lucidos-source threads get the registered Lucidos repo UUID), so the naive `cc_repo_id IS NOT NULL → external` rule would mislabel every legacy Lucidos thread. Legacy rows stay NULL; consumers default NULL to `'lucidos'` via `CodingAgentKind::parse`. New rows are filled by the SessionStarted projection arm via COALESCE-keeps-existing. Consumed by `apply_change`'s `load_apply_kind_context` to dispatch (skip `/harden` + restart + emit `AppUiRefreshRequested` for `'app'`) and by the WIP-preview app-UI route to locate the worktree's app folder. The `coding_agent_bg_bash_pending` column was DROPPED (`20260529155954_drop_coding_agent_bg_bash_pending.sql`). It backed the removed bg-bash propose-gate: the engine used to refuse `ChangeProposed` at idle while a CC background bash task was (thought to be) pending, surfacing this column → a "CC waiting on background tasks" banner with no Apply button until a 5-minute `BgBashWakeRequested` nudge fired. That gate (plus its tracker, timer, event, and `display_section`/`resolve_actions` `bg_bash_pending` params) was removed — changes now propose the instant CC idles, and correctness is covered by harden-at-apply. The `CodingAgentIdled.bg_bash_pending` event field is kept as recorded history but no longer projected. Threads wedged by the old gate auto-recover at boot via `propose_held_back_changes_on_startup` (re-proposes any idle CC thread with a committed diff but no proposal). The same `CodingAgentIdled` projection arm also writes `coding_agent_has_diff = payload.has_changes` (git-truth, drives the WaitingBanner Diff button independently of the proposal lifecycle — the prior bug was a "No changes on this branch" tooltip on a worktree with five commits because `coding_agent_has_diff` was only set by `ChangeProposed`). |
| `notifications` | Projection — from `NotificationCreated` events. Columns include `tap` (jsonb, default `'{"kind":"modal"}'`) — discriminated union controlling what happens on tap. Kinds: `{"kind":"modal"}` (opens inbox modal), `{"kind":"none"}` (passive — marks read with no nav, see `system-knowhow/notifications.md` §4), `{"kind":"navigate","to":{"target":"...","app_id":"...","id":"...","event_id":"...","file_path":"...","url":"...","prompt":"...","settings_view":"..."}}` (delegates to the `navigate_ui` router). CHECK constraint enforces `tap ? 'kind' AND tap->>'kind' IN ('modal','none','navigate')`. The column was JSONB-migrated from the old four-string text form by `20260522152123_notification_tap_jsonb.sql` (rewriting `'open_app'` → `{kind:navigate,to:{target:app,app_id:<row.app_id>}}` and `'open_thread'` → `{kind:navigate,to:{target:thread,id:<row.thread_id>,event_id:<row.event_id>}}`). `event_id` (uuid, nullable) — specific event inside `thread_id` that raised this notification; the §4 in-app matrix uses it for the "user looking at source event" auto-read check (distinct from `tap.to.event_id` which controls the scroll-and-pulse target when the tap navigates). (`push_dispatched` was added by `20260518173257_add_push_dispatched_to_notifications.sql` to gate a cross-device read-marker push fan-out; both the column and the fan-out were dropped in `20260518204120_drop_push_dispatched_from_notifications.sql` — see work-tracker `pwa-read-on-another-device-noise`.) |
| `preferences` | Key-value store with optional `device_id` scoping. |
| `memory_entries` | Vector memory with pgvector embeddings (384-dim). |
| `credentials` | Service credentials. |
| `devices` / `push_subscriptions` | Push notification targets. |
| `device_presence` | Presence projection (transient — no `events` rows). `device_presence(device_id PK, visible_at)` tracks devices with any visible top-level Lucidos tab. `DevicePresenceStore::candidates` returns the device_ids that pinged visible in the last 2 minutes (`PRESENCE_STALE_AFTER`). It is now the **secondary** input to the PresenceCheck gate: `send_push_to_all_with_app` runs the protocol when `max(engine.sse_connections.count(), candidates.len()) > 0` (`expected_pong_count` in `scheduler/push.rs`) and skips it (→ `push_allowed=true` directly) only when BOTH are zero. The live SSE-connection count is the primary signal — it doesn't go stale when iOS suspends the 30s heartbeat on a foregrounded PWA, which is why a heartbeat-only gate fired pushes on active pages. Maintained from transient `DeviceVisible` / `DeviceHidden` SystemEvents. Per-thread focus is no longer persisted — every page reports `focused_thread_id` live in its PresenceCheck pong (see `system-knowhow/notifications.md` §3). |
| `mcp_servers` | MCP server configs. |
| `oauth_accounts` / `email_accounts` | External account configs. |
| `pinned_apps` | Pinned app UIs per device. |
| `browser_logins` / `headless_blocked` | Browser session tracking. |

## Querying threads

No `threads` table. Use:
```sql
SELECT DISTINCT aggregate_id FROM events WHERE event_type = 'CodingAgentIdled';
SELECT payload->>'title' FROM events WHERE aggregate_id = '<id>' AND event_type = 'ThreadTitleGenerated' ORDER BY created DESC LIMIT 1;
SELECT thread_id, branch_name, description, status FROM changes WHERE status = 'pending';
```

## Key event types

- **Thread lifecycle:** `SessionStarted`, `SessionEnded`, `ThreadTitleGenerated`, `ThreadSaved`/`ThreadUnsaved`/`ThreadArchived`
- **Chat / triggers (Lucidos Agent):** `MessageReceived`, `ResponseGenerated`, `ResponseCanceled`, `ResponseAborted`, `TextStreamed`, `ThoughtStreamed` (serde alias `Thinking` for pre-T7 rows), `TodoListWritten` (chat-agent only — replace-whole-list snapshot of the thread's *todo list*; payload = `{ items: [{ content, active_form, status }] }`). These exist on chat AND CC threads — `MessageReceived` is the user typing, regardless of which agent answers. To filter chat-only, join `thread_summaries` and gate on `source = 'chat' AND is_coding_agent = false` (or `source IN ('chat','trigger')` to include triggers).
- **Coding Agent (CC):** `CodingAgentUserMessageSent` (user-typed), `CodingAgentPromptSent` (engine-synthesized: hardening, conflict recovery), `CodingAgentTextStreamed`, `CodingAgentToolCalled`, `CodingAgentToolResult`, `CodingAgentIdled`, `CodingAgentSettingsChanged`. Old `ClaudeCode*` names are serde aliases — write new code against `CodingAgent*`.
- **Changes:** `ChangeProposed`, `ChangeApplied`, `ChangeDiscarded`. Every real merge path in `engine::change_ops::apply_change` (and `apply_now_success` in agent sessions) calls `emit_entity_events_for_change_apply` after `ChangeApplied` to derive per-entity events (`AppCreated`/`AppUpdated`/`AppDeleted`, `ArtifactCreated`/`ArtifactUpdated`/`ArtifactDeleted`) by comparing pre-merge git state vs. post-merge disk state, so frontend caches that subscribe to entity events refresh after a coding-agent thread lands files in `data/apps/<id>/` or `data/artifacts/`.
- **Tools:** `ToolCalled`, `ToolResult`, `HttpRequestSent`, `HttpResponseReceived`, `BackgroundBashStarted`, `BackgroundBashCompleted` (the latter two form the durable record for the `run_bash_background` / `bash_output` / `bash_kill` chat tools — `bash_output` falls back to `BackgroundBashCompleted` after the in-memory registry evicts the task on completion)
- **System:** `NotificationCreated`, `PreferencesChanged` (event-sourced, with projections)
- **Backup / restore (transient):** `BackupProgress`, `BackupCompleted`, `BackupFailed`, `RestoreProgress`, `RestoreCompleted`, `RestoreFailed`. Aggregate = `ops`, `aggregate_id` = `global`. Never persisted to `events` — pure SSE progress. Backup persists its terminal outcome separately via `BackupLastRun` (read by `GET /api/v1/backup/status`). Restore's authoritative progress lives in-memory in `engine.restore_state` (`RestoreState` enum: `idle`/`running`/`completed`/`failed`), which is the SINGLE source both the `Restore*` SSE events AND `GET /api/v1/backup/restore-status` serialize from — so a live stream and a page-reload refetch always render the identical phase/percent. The restore runs detached (`tokio::spawn` in `api/backup.rs::restore_backup`, returns 202) so a dropped client connection can't cancel it; `DELETE /api/v1/backup/restore-status` resets a terminal result to `idle`.
- **Presence (transient):** `DeviceVisible`, `DeviceHidden`, `PresenceCheck`. Aggregate `device_presence` (device-visibility events) or `presence` (PresenceCheck). Never persisted to `events`. `PresenceCheck` is the engine's fan-out **pong trigger** at `NotificationCreated` time — every connected page POSTs `/api/v1/presence-pong` with its live `is_active`, `focused_thread_id`, `event_in_viewport`, and the engine uses the pongs to decide whether to send the OS push (see `system-knowhow/notifications.md` §3). It carries no toast content (that moved to `NotificationToastRequested`). `ThreadFocused` / `ThreadUnfocused` and the `thread_presence` table they fed were retired in favour of the live pong.
- **In-app toast (transient):** `NotificationToastRequested`. Aggregate = `notification`, `aggregate_id` = notification_id. Never persisted to `events`. The engine emits it from the `NotificationCreated` fan-out **only on the push-suppressed branch** (`push_allowed = false` — an active device pong'd in), carrying the toast content (`title`/`body`/`thread_id`/`event_id`/`app_id`/`tap`/`sent_at_ms`). It drives the active-page in-app toast (`system-knowhow/notifications.md` §4). Mutually exclusive with the OS push by construction: the toast-request and the push hang off opposite branches of one `push_allowed` decision, so a device never gets both for one notification (the fix for the "toast AND iOS push at the same time" report).
- **Scheduling:** `ScheduledTaskCreated`, `ScheduledTaskStarted`, `ScheduledTaskCompleted`, `ScheduledTaskDeleted`
- **Trigger groups (audit):** `TriggerGroupCreated`, `TriggerGroupRenamed`, `TriggerGroupReordered`, `TriggerGroupDeleted`. Aggregate = `trigger_group`. Pure organizational folders for the triggers panel; no scheduling, no firing. Each event carries `actor`. Deletes are refused server-side when the group still has member triggers — no event emitted in that case.
- **Apps (audit):** `AppCreated`, `AppUpdated`, `AppDeleted`. Aggregate = `app`. Emitted from three paths: the chat `create_app` tool (`engine/tools/apps.rs`), the HTTP `update_app`/`delete_app`/`write_app_source`/`restore_app_version` endpoints (`api/apps.rs`), and `emit_entity_events_for_change_apply` (see the **Changes** entry above) which derives them from a coding-agent change's file list post-merge. The frontend `processSSEForReferences` listens to all three to refresh `appsList` regardless of which path created the app.
- **Artifacts:** `ArtifactCreated`, `ArtifactUpdated`, `ArtifactDeleted`, `ArtifactImported`, `RepositoryImported`. The `*Created`/`*Updated`/`*Deleted` triple is now also emitted via `emit_entity_events_for_change_apply` for any `data/artifacts/<path>` touched by an applied change, with `source: Some("change_apply")` so consumers can distinguish the path from direct artifact-manager writes.
- **Preferences:** `LanguageSet`, `TimezoneSet`
- **Devices / pinned apps (audit):** `DeviceRegistered`, `DeviceRenamed`, `DevicePushChanged`, `DeviceDeleted`, `PinnedAppPinned`, `PinnedAppUnpinned`. Each carries `actor` so the timeline attributes the change.
- **Repositories / credentials / oauth (audit):** `RepositoryAdded`, `RepositoryRemoved`, `CredentialCreated`, `CredentialUpdated`, `CredentialDeleted`, `OAuthAccountDeleted`. `Credential*` payloads NEVER carry the secret value — only the service name.
- **Data file ops (audit):** `DataFileWritten`, `DataFileDeleted`, `DataFileEdited`. Emitted by `PUT/DELETE/POST /api/v1/data/*` so the timeline records who edited which `data/` path.
- **Apply All batches:** `ApplyAllBatchStarted`, `ApplyAllBatchCompleted`. Aggregate = `apply_all_batch`, `aggregate_id` = `batch_id` (UUID). Persisted (durable across restart). The HTTP `apply_all_changes` handler emits `Started` with every pending change ID + actor; the in-engine driver task (`start_apply_all_driver`) advances the batch as `ChangeApplied` / `ChangeApplyFailed` arrive and emits `Completed` with `applied: Vec<Uuid>` + `failed: Vec<ApplyFailure>` when every member resolves. Without this pair the rest of the batch is abandoned at the first conflict.
- **Engine supervisor (audit):** `EngineSupervisorRespawned`. Aggregate = `engine`, `aggregate_id` = `supervisor_pid`. Payload: `{old_pid, exit_code, died_at, supervisor_pid}`. Bash supervisor (`scripts/lib/engine_supervisor.sh`) writes a sidecar JSON at `<workspace>/.lucidos/engine.last-death.json` when its child died unexpectedly (exit code other than 0/130/138); the next engine reads + emits + deletes the sidecar at startup (see `engine::supervisor_respawn_sidecar::emit_if_present`). Surfaces silent engine deaths (SIGKILL, panic, process-group kill) in the audit timeline. No `actor` — engine drove it.
- **Email (audit):** `EmailSent`. Aggregate = `email`, `aggregate_id` = `account`. Emitted by the `/api/v1/email/send` HTTP handler on a successful SMTP send. Payload carries only envelope metadata (`account`, `to`, `cc`, `bcc`, `subject`, `attachment_count`, `actor`); the message body is intentionally NOT broadcast — it's user data that would fan out over SSE to every connected client.
- **Proxy modules (audit):** `ProxyModulesReloaded`. Aggregate = `proxy_modules`, `aggregate_id` = `global` (a single auth-modules map per workspace). Emitted by `POST /api/v1/proxy-modules/reload` after the WASM map swap succeeds. Payload = `{count, names, actor}` so a post-mortem of a sign-handshake regression can read when and to what the surface changed.
- **Apps (transient):** `AppUiRefreshRequested`. Aggregate = `app`, `aggregate_id` = `app_id`. Not persisted — UI signal, not audit. Emitted from `apply_change` for *app coding-agent thread* applies when any merged file is iframe-bundled (HTML/CSS/JS/manifest + the asset allow-list in `git_ops::any_iframe_bundled_file_changed`). Consumed by the SDK in any open iframe of `app_id` to reload its src so the user sees the merged content without a manual refresh.
- **Other:** `SessionResumed`, `ChangeDiscarded`, `ScheduledTriggerCompleted`

## Column notes

Timestamp is `created` (not `created_at`). `aggregate_id` is `text` (not uuid) — cast when joining: `aggregate_id = c.thread_id::text`. `thread_id` column is legacy; prefer `aggregate_id`. `payload` is `jsonb`.
