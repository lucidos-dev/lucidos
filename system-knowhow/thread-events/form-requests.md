## Form requests

A *form request* is something the agent put in front of the user to fill in or confirm. Each carries a `request_id` and a `payload` string (the JSON the client renders from, never a secret). It stays open until exactly one `FormRequestResolved` names its `request_id`. An open request changes no thread status.

Only the source named in a row opens its form. A `run_bash`, MCP or fetched result that starts with a form-request prefix opens nothing. The request is persisted, so a client that missed its stream frame still finds it through `GET /api/v1/form-requests/pending`, read on every stream open. The transcript shows each request in its turn, with an Open button while it waits.

Emitted once per request. | per-action | yes | yes |

The `QUESTION_OVERTAKEN_EVENT_TYPES` constant lists the events that mean a `UserQuestionAsked` is no longer the thread's latest interactive point. Once one lands after a question, the next typed text starts a fresh follow-up, not a `FreeText` answer. Two categories:

- **Terminal**: `ResponseAborted`, `ResponseCanceled`, `ResponseFailed`, `CodingAgentIdled`.
- **Agent progression**: coding agent (`CodingAgentTextStreamed`, `CodingAgentToolCalled`, `CodingAgentPromptSent`) and chat (`TextStreamed`, `ThoughtStreamed`, `ToolCalled`, `ToolResult`).

The coding-agent progression set defends against a race. A coding agent can emit a question alongside sibling tool calls, and the siblings keep emitting while the question blocks. Without this filter, the user's next comment would be silently absorbed as a `FreeText` answer to the dead question.

A `CodingAgentToolResult` is not in the list. It completes a call issued earlier, and a call issued after the question already overtakes it through its own `CodingAgentToolCalled`. A result ends a question only when its `tool_use_id` is the question's own, which is how Claude Code records an Esc'd `AskUserQuestion`. A command started before the question can finish while the card is open, and that late result leaves the card live. It also leaves the thread status at `waiting_for_user_answer`, the same for a permission card.

An answer carrying composer text **consumes the thread's compose slot** in the same transaction that records the accepted answer. That is a `FreeText`, or a `MultiSelected` with `text` or images. The *compose epoch* advances, so a draft write composed before the answer cannot apply after it. The stored draft clears only when it is the submitted content or an earlier state of it. A `ThreadComposeChanged` tells every device what that left.

A click-only answer submits no text, so it consumes nothing, and another device's draft survives. An optional `compose` report on `UserQuestionAnswered` restores the accepted compose state during projection replay, without overwriting a newer epoch.

The FreeText fast-path also requires a **human-authored** follow-up (`ActorMode::Human`). Agent- and engine-driven re-entries are not the user's answer and fall through. Example: a **child-thread completion** re-opens the parent via `notify_parent_of_child_completion` with `ActorMode::Agent`, feeding a `[CHILD THREAD COMPLETED] …` block. Without the guard, that block became a bogus `UserQuestionAnswered { FreeText }` (actor = `thread_link`/`child`) and killed the user's open question. Now it falls through to the injection fast-path (queued as `ReentryFromEngine`). The question stays live, and the child's result runs right after the user answers.

## Thread lifecycle

| Event | When it fires | Volume | Persisted | Triggerable |
|---|---|---|---|---|
| `ThreadStarted` | A thread was created in `composing` state (debounced first user input on a fresh compose). Carries `mode: String` (initial compose mode), optional `actor`. A seeded start fills the draft once: `recovered_compose` after a restore, or `agent_draft` (`text`, ordered `image_hashes`, `selection`, `drafted_by_thread_id`) from `lucidos threads create-draft`. | lifecycle | yes | yes |
| `ThreadDiscarded` | A composing thread was explicitly discarded (DELETE /threads/:id). Terminal: the state-machine guard rejects all later compose mutations with 410 Gone. | lifecycle | yes | yes |
| `HomeThreadCreated` | The workspace's home thread was created: an active chat thread titled "Home", with no message yet. The engine emits it once per workspace: at its first boot, or at the first model call no thread made, whichever comes first. No payload. | lifecycle | yes | yes |
| `ThreadTitleGenerated` | The title-generation pass produced a title for the thread (background, after enough body to summarize). Never on the *home thread*, which only the user names. | lifecycle | yes | yes |
| `ThreadTitleRenamed` | The user manually renamed the thread. | lifecycle | yes | yes |
| `ThreadSaved` | User pinned the thread. A pinned thread is never archived, so pinning an archived thread also moves it back to the inbox. Empty payload. | lifecycle | yes | yes |
| `ThreadUnsaved` | User unpinned the thread. Also clears its custom folder. Empty payload. | lifecycle | yes | yes |
| `ThreadMovedToFolder` | User filed a pinned thread in a custom folder. Carries `folder`, an id from the `thread_folders` preference, or null for plain Pinned. Unpin, archive and discard clear the folder. | lifecycle | yes | yes |
| `ThreadArchived` | The thread was archived. Empty payload. `actor` says who: a device for the Archive button, or `{"kind":"api","mode":"agent","source_thread_id":…}` for an *agent archive* by that thread (ADR 0310). The engine never archives a thread by itself. The user's Archive unpins a pinned thread. An agent archive refuses one (`thread_pinned`), and an unattended trigger run never archives one. | lifecycle | yes | yes |
| `ThreadArchiveRequested` | The thread's own agent asked to be archived once its turn ends (`threads` 'archive' with `current`). Empty payload; `actor` names the agent thread. The archive lands as a `ThreadArchived` after the thread settles, and a newer `MessageReceived` closes the request. | lifecycle | yes | yes |
| `ThreadUnarchived` | The user moved an archived thread back to the inbox: Archive all's **Undo**, or **Move to Current**, which takes the sub-threads too (`POST /api/v1/threads/unarchive`, ADR 0349, ADR 0378). Empty payload; `actor` is the user's device. Bumps no recency, so the thread returns to where it sat. | lifecycle | yes | yes |
| `ThreadReadRequested` | The yes half of a turn's *read decision*. A chat agent can record it with `request_read` and a coding agent can use `lucidos request-read yes`. In a trigger run, only the engine records yes (ADR 0747). Carries `parent_report` for yes on agent-opened turns in integrated sub-threads and for requests in sub-threads spawned with `wake` or `wake-when-all-done` on agent-opened turns when no unseen user yes stands. `actor` names the agent thread, and is absent when the engine forced the decision. Sets the *read request*, which lists the thread in the drawer's Review group once its turn ends. In an integrated sub-thread, a yes with `parent_report` records the decision without setting a request or superseding an unseen user request. A change that already lists the thread replaces it: a ready change, or independent work held for a missing harden (ADR 0421). A trigger run with a read request lands in Current. Never counts as attention. | lifecycle | yes | yes |
| `ThreadReadNotRequested` | The no half of a turn's *read decision*: the agent decided its reply needs no reading (`request_read` with `read: false`, or `lucidos request-read no`). Every turn that ends normally records one decision. Carries `supersedes_request`, true only when the unseen request it follows was a `parent_report`, and absent otherwise. `actor` names the agent thread, and is absent when the engine forced the decision. With `supersedes_request` it clears that request, since the parent already has the earlier report. Otherwise it projects nothing: it never clears an unseen request, and a trigger run that decides no stays archived (ADR 0417). | lifecycle | yes | yes |
| `ParentWakeRequested` | The yes half of a child thread's *wake decision*, which only a child with no *wake mode* makes. The engine also records it for any child whose turn it cut short, or which ended with an empty reply: its parent must act on this turn's report, so the report wakes it (`wake_parent` with `wake: true`, or `lucidos wake-parent yes`). Empty payload; `actor` names the child's agent, and is absent when the engine decided at the turn end. Sets the child's `parent_wake_requested` until its next turn starts, or until the report it governs is delivered. | lifecycle | yes | yes |
| `ParentWakeNotRequested` | The no half of a child thread's *wake decision*: its parent need not act now (`wake_parent` with `wake: false`, or `lucidos wake-parent no`). A clean finish then files the report on the parent as a `ChildReportFiled`, which wakes nothing. A failure still wakes it. Empty payload; `actor` as for `ParentWakeRequested`. | lifecycle | yes | yes |
| `ThreadReplySeen` | The user saw the reply a *read request* pointed at: its end stayed on screen for the seen dwell (`POST /api/v1/threads/:thread_id/read-request/seen`). Carries `seen_version`, the thread's summary version the client saw; `actor` is the user's device. Recorded only while that version still holds a pending request, and clears it. On a gateway with two or more people a device a person holds records it with `personal: true`, which clears the request for that person only. A human message or an archive clears a request too, with no event of its own. | lifecycle | yes | yes |
| `ThreadTriageProposed` | The Lucidos Agent proposed a *thread triage* in this thread (`threads` 'triage', ADR 0349). Carries `entries: [{thread_id, action, reason}]`, where `action` is a triage action name. `apply_triage` acts only on these threads, and only after a user reply newer than this event. `actor` names the agent thread. | lifecycle | yes | yes |
| `RootThreadDriverTaken` | Someone became the *driver* of a root thread and its sub-threads (ADR 0623): Take or Take over (`lucidos.threads.users.take`, `POST /api/v1/threads/:thread_id/users/take`), or an answer to a gate from someone who did not drive it. Recorded on the family root. Empty payload; `actor` names the new driver: a device, or a trigger fire whose actor email a user holds. An answer from nobody records none. Roles are never authority. | per-action | yes | yes |
| `RootThreadDriverReleased` | The driver gave the role up (`lucidos.threads.users.release`). Recorded on the family root, empty payload, `actor` names them. The root thread has no driver until someone takes it, so its pushes reach the whole team. | per-action | yes | yes |
| `RootThreadGateEscalated` | A gate waited on its driver past `driver_timeout_hours`. Recorded once per gate on the family root, with no `actor`. Carries `gate_thread_id` (the thread the card is on) and `tool_use_id`. Until the gate is answered, the root thread's pushes reach the whole team. The driver keeps the root thread. | per-action | yes | yes |
| `RootThreadWatched` | Someone started watching a root thread: its pushes reach them beside the driver. Recorded on the family root. Tapping Watch (`lucidos.threads.users.watch`) records an empty payload, and `actor` names them. A *user mention* (ADR 0649) records `user_id`, the user mentioned, and `actor` names the sender. | per-action | yes | yes |
| `RootThreadUnwatched` | Someone stopped watching a root thread, from any of their devices (`lucidos.threads.users.unwatch`). Recorded on the family root, empty payload, `actor` names them. | per-action | yes | yes |
| `UserOnlyMessagePosted` | A user wrote to the other users in a thread, not to its agent: a *user-only message* (ADR 0649). Team gateway only. Carries `text`, optional `user_image_hashes`, `device_id` and `mentioned_user_ids`; `actor` names the sender's device. It starts no turn and moves no status. The agent reads it as context on its next woken turn. It can be a thread's first event; a take-back that commits first refuses delivery. | per-action | yes | yes |
| `AgentPaused` | Typed messages in a thread stopped waking its agent: the *agent pause* (ADR 0649). Carries `cause`: `mention` (a message mentioned only people) or `chip` (`POST /api/v1/threads/:thread_id/agent-pause`). `actor` names who paused. A running turn carries on. | per-action | yes | yes |
| `AgentResumed` | Typed messages in a thread wake its agent again. Carries `cause`: `mention` (a message mentioned the agent) or `chip`. `actor` names who resumed. The last `AgentPaused` or `AgentResumed` on a thread is its pause state, which `GET /api/v1/threads/:thread_id/agent-pause` answers as `{ paused }`. | per-action | yes | yes |
| `ThreadHoldPlaced` | A *hold* reached this thread (ADR 0805): Lucidos starts no turn here by itself until Resume. Recorded on the root and on every unarchived sub-thread it reached. Carries `reason`, `hold_id` (shared by every thread one hold reached) and `root_thread_id`. `actor` names who placed it. Running turns in the tree stop with cause `hold`. | per-action | yes | yes |
| `ThreadHoldLifted` | A hold on this thread ended. Carries `hold_id` and `cause`: `resume` (Resume on the root) or `archived` (the owner archived the thread). The last placed hold without a lift is the thread's hold. | per-action | yes | yes |
| `AutomationPaused` | Legacy: the retired automation pause, which Hold replaced. Stored rows still read as a hold rooted at their own thread. Nothing records one now. | per-action | yes | yes |
| `AutomationUnpaused` | Legacy: the retired end of an automation pause. Stored rows read as a lifted hold. Nothing records one now. | per-action | yes | yes |
| `PermissionGranted` | The owner's pick on a *permission request* granted a *permission*. Carries `permission_id`, `action`, optional `breadth`, `lifetime` (`once`, `this_thread`, `until_plan_lands`, `standing`), `holder` (`{ kind: "thread", thread_id }`, `{ kind: "trigger", trigger_id }` or `{ kind: "workspace" }`), `request_tool_use_id` and `picked_by`. `picked_by` is the receipt: `{ kind: "tap" }`, `{ kind: "typed" | "spoken", message_event_id }` naming the owner's words (a spoken pick the call's talker made names none), or `{ kind: "batch", permission_id }` for a pick a confirmed batch made. `actor` is the owner's device. Only a device's pick of a granting option records one. Spoken words pick only when the permission-answer judgment is sure. Older receipts can carry `kind: "typed"`. A tool card's "Allow for this thread" also carries `pattern`, the grant line the lane's own matcher reads. | per-action | yes | yes |
| `PermissionSpent` | A once permission covered the action it allowed, so it ended. Carries `permission_id`. A unique index refuses a second spend. | per-action | yes | yes |
| `PermissionRestored` | The gateway explicitly refused without making a change. Carries `spent` and `restored`: the spent once permission and its fresh copy. Keeps the same holder, action, request and turn boundary. Unknown outcomes stay spent; a unique index permits one restore per spend. | per-action | yes | yes |
| `PermissionRevoked` | Someone revoked a permission (`lucidos permissions revoke`, `DELETE /api/v1/permissions/:permission_id`). Carries `permission_id`. `actor` names who. A standing tool grant's revoke lands in the thread it was granted in, or in the home thread. | per-action | yes | yes |
| `PermissionRequestPrepared` | An agent prepared a *permission request* on its own thread with `lucidos ask-permission` (`POST /api/v1/permission-requests`). Carries `request_id`, `request` (the typed request, as on `UserQuestionAsked.permission_request`) and `card`, the words and options Lucidos wrote. Grants nothing by itself: the card appears when the agent asks its question tool with `request_id` as its only question. A snapshot restore ends every request prepared before it. | per-action | yes | yes |
| `BatchItemRan` | One item of a confirmed *batch* ran, on the thread that raised it. Carries `permission_id` (the spent grant), `index` (from 0), `item` and `outcome`: `{ kind: "applied" }`, `{ kind: "partly_applied", reason }` when a refusal stopped a workspace classification after some workspaces moved, or `{ kind: "skipped", reason }` when the item could not run. A `workspace_deletion` item lists the requested slugs. Its receipt uses `partly_applied` when some deletions failed or their outcome is uncertain. An applied trigger grant lands as a `TriggerUpdated` from the owner's device. An applied item's own `UserQuestionAnswered` lands on its thread, as the owner's device. A `reviewed_trigger_program_grants` item saves the listed program grants without firing the trigger. Older cards carry one grant as `reviewed_trigger_program_grant`. For that review, `permission_id` identifies the card's receipt. | per-action | yes | yes |
| `ImageUploaded` | A user attached an image to a compose draft (POST /api/v1/threads/:id/blobs). Carries `hash` (sha256, sole identity), `mime`, `byte_size`, optional `actor`. Bytes live exactly once at `data/blobs/<hh>/<hash>.<ext>`. | per-action | yes | yes |
| `TriggerStarted` | A scheduled or event-driven trigger run started. Carries `trigger_id`, optional `trigger_name`, optional `prompt`, optional `invocation: TriggerInvocation` (`Schedule` or `Event { event_type, event_id?, thread_id? }`). That `thread_id` is set only for thread-scoped source events, and script triggers see it as `TRIGGER_EVENT_THREAD_ID`. Also optional `origin`, `go_to_review: bool`, optional `model`, `reasoning_effort`, `provider` and `continue_key`. Wire aliases: `task_id`, `task_name` (from when triggers were "scheduled tasks"). `model` / `reasoning_effort` / `provider` record what the fire ran on: the trigger's own pin, else the account trigger model; for the provider, the model's preferred route. This is a trigger thread's *starter* event, with no `MessageReceived`, so per-thread model memory reads these fields. A follow-up on a trigger thread reuses the fire's model instead of the account chat model. Absent on older runs. | lifecycle | yes | yes |
| `TriggerCompleted` | A trigger run finished. Carries `trigger_id`, optional `trigger_name`, optional `result_summary`. Same aliases. `result_summary` is always a non-empty, single trimmed line. A script that exits 0 with no stdout falls back to its last non-empty line, else `"<name> completed (exit <code>, no output)"`. An intent run with no final text falls back to `"<name> completed (no output)"`. So idle-detector triggers never read as a flood of no-op fires to the learning and audit sweeps. | lifecycle | yes | yes |
| `TriggerRunInterrupted` | Boot reported a trigger fire cut by an engine restart. Carries `trigger_id`, `trigger_name`, `fire_event_id`, and `retry`. Restores the inbox and preserves the pin. See the payload reference below. | lifecycle | yes | yes |
